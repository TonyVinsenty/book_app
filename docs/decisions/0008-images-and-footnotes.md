# 0008. Картинки и сноски

- Статус: предложено (архитектор, 2026-10-22)
- Связано: 0002 (модель, хранение, позиция — уточняет п. «Иллюстрации»), 0003 (вёрстка), 0004 (токены, скорочтение), 0005 (импорт, обложка), 0006 (тесты)

## Контекст
Этап 12: иллюстрации и обложка внутри текста, сноски по нажатию. Сейчас FB2 и EPUB картинки и сноски выбрасывают (метки сносок тоже); в модели уже есть `ImageBlock(assetId, width, height)` и `Span(noteRef, noteId)`, вёрстка для `ImageBlock` возвращает `null`, страница без слов уже допускается (`ChapterPage.hasWords`). Книги разбираются в изоляте; уже добавленные книги разбираются заново при росте версии парсера (`BookOpener`). Ограничения: телефон (память iPhone), без нового нативного кода, пакеты — только если своё сложнее.

## Решение
**1. Хранение картинок — файлами.** `books/<id>/img/<n>.<ext>` (`assetId` = `"<n>.<ext>"`, номера по порядку в книге). Парсер не держит все картинки в памяти: отдаёт каждую в `ImageSink` (`void add(String assetId, Uint8List bytes)`), в импорте и повторном разборе — запись в изоляте во временную папку `img.new/`, после записи модели — замена `img/` целиком (как `_replace` для файлов). В тестах — сток в памяти. Тип и размер в пикселях — по заголовку файла своим кодом (JPEG SOF, PNG IHDR, GIF, WebP VP8/VP8L/VP8X, BMP; ~80 строк, рядом с `book_cover.dart`) — без пакета `image`. Размер нужен вёрстке без декодирования.

**Пределы** (картинка не проходит — пропускается, текст не страдает): не JPEG/PNG/GIF/WebP/BMP или размер не прочитан; > 20 МБ; > 50 Мпикс (иначе декодер на телефоне может уронить приложение); обе стороны < 16 пикс (распорки); на книгу — не больше 2000 картинок и 300 МБ. Одинаковые ссылки на одну картинку — один файл.

**2. Картинки в модели.** `ImageBlock` — отдельный блок; `width`/`height` всегда заполнены (без них блок не создаётся).
- FB2: `<image l:href="#id">` в теле → блок; `<binary id>` (часто после текста) → декодируется только для упомянутых id; нет `binary` или битый base64 → блок убирается в конце разбора. `coverpage` → первый блок первой главы (обложка — первая страница книги).
- EPUB: `<img src>`, `<svg><image xlink:href>` (обёртка полностраничных картинок) → блок; чистый SVG-рисунок — пропускается (Flutter без пакета его не рисует; `flutter_svg` — при необходимости позже). `<img>` внутри абзаца режет абзац: часть до, картинка, часть после. Файл spine только с картинками приклеивается к следующей главе с текстом (в конце книги — к предыдущей); так обложка становится первой страницей. Глава без слов не создаётся.
- TXT: без изменений.

**3. Сноски в модели.** `BookContent.notes: Map<String, Note>`, `Note { label?, blocks: [Block] }` — в том же `content.v<N>.json.gz`, вне `sections`: не в потоке чтения, не в оглавлении, не в процентах и словах. Метка в тексте = **текст метки в `text` блока** (без скобок: `[12]` → `12`, пустая → `*`) + `Span(start, end, noteRef, noteId)` поверх него. Так смещения вёрстки и подсветки совпадают с моделью.
- FB2: `<a type="note">` и ссылки `#id` на тело `notes`/`comments` → метка; секции этих тел → `notes` (заголовок секции — `label`).
- EPUB: метки, которые сейчас распознаются и выбрасываются (`noteref`, `[2]`, `<sup>`-ссылки…), становятся метками; `noteId` = `"<файл>#<id>"`. Текст сноски: `aside`/`epub:type footnote|endnote` (в потоке и сейчас пропускаются) — весь элемент; иначе — второй проход по файлам с целями (в т. ч. не из spine): ближайший блочный элемент с якорем (`p`, `li`, `dd`, `div`, `section`, `aside`). Обратная ссылка («↩», `1)` на исходную метку) убирается. Файл «Примечания» в spine EPUB остаётся в потоке, как сейчас.
- Сноска внутри сноски — такие же `noteRef` в `Note.blocks`. Цель не найдена — метка остаётся, но неактивна (серая).

**4. Токенизатор.** Символы под `noteRef` прозрачны: не образуют слов, не рвут слово (`сказал¹,` → слово «сказал,»), в показе слова вырезаются. Метки сносок исчезают из RSVP по слову и фразе, из «проступающего» текста и из подсчёта слов сами. `tokenizerVersion` → 3.

**5. Совместимость и позиция.** Версии парсеров растут (FB2 и EPUB) → уже добавленные книги тихо разбираются заново при открытии (механизм есть), картинки извлекаются тогда же. Метки и картинки сдвигают номера блоков и смещения, поэтому якорь ненадёжен: **при повторном разборе, если число слов не изменилось, `wordIndex` сохраняется как есть** (слова те же — метки и картинки слов не дают), иначе — по якорю. Обложки в библиотеке не меняются. Миграции базы нет.

**6. Вёрстка (уточняет ADR 0003).** Картинка — блок «не делится», ширина = ширина текста, но не больше натурального размера (1 пикс картинки = 1 точка экрана: виньетки остаются маленькими), высота — не больше высоты страницы (тогда уменьшается по высоте), по центру. Не помещается в остаток страницы — уходит на следующую целиком (внизу остаётся пусто). Размер считается из `width/height` без декодирования, поэтому фоновая разметка книги и кэш страниц работают как раньше; `layoutVersion` растёт. Рисование: `Image.file` с `cacheWidth` = ширина на экране × плотность (память ограничена размером экрана), картинки соседних страниц заранее (`precacheImage`), битый/пропавший файл — рамка со значком. Ночная тема — картинка чуть приглушена (если владелец согласен).
Страница только с картинкой слов не имеет: место на ней не сохраняется (как сейчас для таких страниц); книга, открытая впервые (позиция 0), начинается с первой страницы — с обложки.

**7. Просмотр картинки.** Тап по картинке (в средней зоне; края — листание, как всегда) → полноэкранный просмотр на тёмном фоне: `InteractiveViewer` (встроен во Flutter) — зум двумя пальцами до ×5, двойной тап — ×2,5 в точке / назад, закрыть — тап, свайп вниз или «назад». Декодирование — не больше 4096 пикс по длинной стороне. Пакет `photo_view` не нужен.

**8. Сноски на экране.** Метка — маленькая, акцентным цветом: цифры заменяются на надстрочные символы Юникода 1:1 (`¹²³⁴…`, смещения не меняются); прочие метки — уменьшенным шрифтом. В шрифты (`tool/fonts/build_fonts.py`) добавляется диапазон U+2070–U+209F. Зона касания метки расширена (~44 точки) и важнее листания и долгого нажатия. Тап → нижняя панель с текстом сноски (шрифт книги, мельче; прокрутка; до ~60% экрана; закрыть свайпом вниз или тапом мимо). Сноска в сноске — открывается в той же панели, со стрелкой «назад». Тексты — в ARB.

**9. Скорочтение.** RSVP (слово и фраза): картинки и метки пропускаются (у токенов их нет); отдельной паузы на картинку нет. Ведущая подсветка: идёт по словам; страницу только с картинкой показывает ~2 с и листает дальше (иначе картинку не увидеть).

**10. Нативный код iOS и Android — ноль.** Новых пакетов нет.

## Отвергнуто
- **Картинки внутри `content.json.gz` (base64) или в SQLite**: модель грузится целиком при каждом открытии — память и время растут на десятки МБ без пользы.
- **Доставать картинку из исходника по требованию**: для FB2 пришлось бы разбирать весь файл; файлы на диске проще и быстрее.
- **Метка сноски нулевой длины (только позиция, без текста)**: не трогает смещения, но вёрстке пришлось бы вставлять текст и пересчитывать все касания и подсветку.
- **`WidgetSpan` для надстрочной метки**: ломает соответствие смещений и выравнивание по ширине.
- **Пакеты `photo_view`, `image`, `flutter_svg`**: зум и чтение заголовков — встроенным и своим кодом; SVG-рисунки в книгах редки.
- **Уменьшать картинку под остаток страницы**: меньше пустоты, но картинки становятся разного размера и усложняется кэш страниц. Можно добавить позже.
- **Позиция по якорю при повторном разборе** (как раньше): после появления меток и картинок место «съезжало» бы внутри абзаца.

## Последствия
- Все FB2 и EPUB при первом открытии после обновления разбираются заново (секунды на большой книге — один раз); место сохраняется.
- Место на диске: + размер картинок книги (до 300 МБ на книгу по пределу).
- После открытия картинки на странице только с картинкой место запоминается по следующему тексту: при повторном открытии книга откроется на странице после картинки.
- Сноски EPUB из «необычной» разметки могут не найтись — тогда метка серая, текст не теряется; набор «трудных книг» ловит такие случаи.
- SVG-рисунки (не обёртки) пока не показываются.
