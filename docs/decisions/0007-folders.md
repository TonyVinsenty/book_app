# 0007. Папки: своя папка, подключённые папки, досканирование

- Статус: принято (архитектор, 2026-10-21; владелец 2026-10-21: файлы в папках не удаляются, подборка по папке — галочкой, много книг — сразу с полоской)
- Связано: 0001 (свой канал, без пакетов), 0005 (конвейер импорта, очередь, раздел «Папки — что реально можно»), 0006 (структура, сторожа, фейки)

## Контекст
ADR 0005 уже решил главное: книга из папки **копируется** в библиотеку, папка пересканируется только при открытии приложения (фона на iOS нет), удаление файла из папки книгу не удаляет. Не решено: где хранить папки и что уже видели, как не «воскрешать» удалённые книги, как сравнивать быстро, лимиты, протухшие разрешения, интерфейс. Сейчас: база v4 (`lib/data/db/app_database.dart`) лежит в Application Support — скрыта от пользователя, поэтому `Documents` на iOS свободна под «свою папку»; `Info.plist`: `LSSupportsOpeningDocumentsInPlace = false`, `UIFileSharingEnabled` нет; приёмник входящих файлов (`AppDelegate.swift`) уже копирует с `startAccessingSecurityScopedResource` и удаляет только копии из `Documents/Inbox`; `ImportQueue` удаляет отданный ей файл после обработки.

## Решение

**1. Своя папка.**
- **iOS:** `UIFileSharingEnabled = true` + `LSSupportsOpeningDocumentsInPlace = true` → в «Файлах» появляется «На iPhone → BookApp» (это `Documents`). Сканирует её **Dart** (`getApplicationDocumentsDirectory` + `Directory.list`) — **Swift ноль**. Пропускаем `Inbox` (системные копии «Открыть в» — их забирает приёмник; пустую `Inbox` Dart удаляет), скрытые файлы и папки (`.Trash` — «Недавно удалённые»).
- Побочный эффект второго ключа: «Открыть в» из «Файлов» отдаёт **сам файл, а не копию**. Приёмник к этому готов (копирует со «scope», не удаляет ничего вне `Inbox`) — но проверить на iPhone обязательно.
- **Android:** видимой «своей папки» нет (ADR 0005). Технически та же логика сканирует `getExternalStorageDirectory()/Books` (`Android/data/com.tonyvinsenty.bookapp/files/Books`): файловым менеджерам Android 11+ она не видна, но видна **с компьютера по кабелю** и через `adb push` — так весь путь «положил файл → книга появилась» проверяется на эмуляторе без нативного кода. В экране «Папки» — одна строка подсказки. Удаляется вместе с приложением (как и библиотека).

**2. Подключённые папки** — свой канал `files` (ADR 0001), новые методы; ссылка на папку для Dart — непрозрачная строка `ref`:
| Метод | Android (`MainActivity.kt`, ~100 строк) | iOS (`AppDelegate.swift`, ~100 строк) |
|---|---|---|
| `pickFolder()` → `{ref, name}` / null | `ACTION_OPEN_DOCUMENT_TREE` + `takePersistableUriPermission(READ)`; `ref` = URI дерева | `UIDocumentPickerViewController(forOpeningContentTypes: [.folder])`; `ref` = закладка (`bookmarkData()`, base64) |
| `listFolder(ref)` → `{files: [{key, name, size, modified}], ref?}` или ошибка `lost` | `DocumentsContract` (запрос детей по каждой папке, рекурсивно), в фоновом потоке; `key` = documentId | разрешить закладку, `startAccessing…`, `FileManager.enumerator` (`skipsHiddenFiles`), на фоновой очереди; `key` = путь внутри папки; закладка «stale» → новая в ответе (`ref`) |
| `copyFolderFiles(ref, keys)` → пути копий | копия в `cache/folders/<n>/<имя>` | копия в `tmp/folders/<n>/<имя>` (общая `copyFile`) |
| `releaseFolder(ref)` | `releasePersistableUriPermission` | ничего |
Фильтр по расширению — в нативной части (меньше данных через канал): `.fb2 .epub .txt .zip` (без регистра; `.fb2.zip` — это `.zip`). Формат по содержимому определяет конвейер, как раньше. Файл, который не удалось скопировать, приходит путём «в пустоту» (как у входящих).
- **iCloud Drive (iOS):** не скачанный файл (`.имя.icloud`) — `startDownloadingUbiquitousItem`, в этот раз пропускаем; следующее сканирование его возьмёт. `NSFileCoordinator` не используем (лишняя сложность для чтения книг).
- **Android:** корень памяти и корень «Загрузок» система выбрать не даёт (Android 11+) — подсказка в ARB: «создайте папку, например „Загрузки/Книги“». Лимит постоянных разрешений (128+) нам не грозит; при отключении папки разрешение отдаём.
- **Протухшие разрешения:** iOS — закладка не разрешается или нет доступа; Android — URI нет в `persistedUriPermissions` или запрос падает → `lost`. Папка помечается «нет доступа» (книги остаются), в «Папках» — «Подключить заново»: тот же выбор, `ref` заменяется, память о файлах сохраняется (та же папка → ничего не импортируется заново; другая → дубли отсеет хэш).

**3. База v5** (миграция v4→v5 — только `createTable` ×2; снимок `drift_schema_v5.json`; тест миграции v1–v4 → v5):
- `Folders`: `id` (autoinc), `kind` (`textEnum`: `own` / `picked`), `name`, `ref` (null у своей), `addedAt`, `scannedAt` (null), `lost` (bool, по умолчанию false). Строку своей папки создаёт `FolderRepository` при запуске (на iOS и Android), её нельзя отключить.
- `FolderFiles` — **память о том, что уже видели**: `folderId` (FK, `ON DELETE CASCADE`), `key`, `size`, `modified` (мс; 0 — неизвестно), `seenAt`; ключ — (`folderId`, `key`). Ссылки на книгу нет: она не нужна для правил ниже (и архив даёт несколько книг).

**4. Сканирование.**
- **Когда:** после первого кадра при запуске (не задерживая открытие последней книги), при возврате в приложение (`AppLifecycleListener.onResume`), сразу после подключения папки, жестом «потянуть вниз» в библиотеке. Одно сканирование за раз; запрос во время сканирования — игнорируется. Источник — виджет-наблюдатель в `MaterialApp.builder` рядом с `IncomingBooks`.
- **Как:** список файлов (`FolderSource`: `LocalFolderSource` — Dart, для своей папки; `ChannelFolderSource` — канал) → чистая функция `planScan(entries, known)` → `toImport` (нет в памяти или изменились `size`/`modified`; `modified = 0` → только размер) и `forgotten` (в памяти, но файла нет — строка удаляется). **Хэш считается только для `toImport`** — его уже считает конвейер. Новые файлы копируются во временную папку и идут в общую `ImportQueue` — очередь по-прежнему владеет копией и удаляет её (оригинал в своей папке iOS никогда не отдаётся очереди напрямую). Строка `FolderFiles` пишется **после** результата файла (любого: добавлен, дубль, ошибка) — сбой посередине просто повторит файл в следующий раз, дубль отсеет хэш.
- **Рекурсивно**, глубина до 8; не больше 5000 файлов-книг на папку (дальше — отметка «папка слишком большая, взяты первые 5000» в «Папках»); файл больше 300 МБ — пропуск с записью в память (лимиты архива — ADR 0005).
- **Тихо:** импорт из папок никогда не открывает книгу и не переходит между экранами; дубль из папки **не поднимает** книгу в списке (`touch: false` в импортёре — иначе первое подключение папки перемешало бы библиотеку). Итог — обычной строкой очереди в библиотеке («Добавлено 3, уже были 2»); в читалке ничего не показывается. Повторное сканирование без новых файлов ничего не показывает; битый файл сообщается один раз (он в памяти).
- **Скорость:** повторное сканирование папки на 1000 книг без изменений — до 1 с на телефоне (только список и сравнение).

**5. Правила жизни книги.**
- Файл удалён из папки → книга остаётся (строка памяти удаляется). Файл вернули → снова импорт; если книга есть — тихий дубль.
- Книга удалена из библиотеки → файл в папке **не трогаем** и книга **не воскресает**: файл есть в памяти. Вернётся, только если файл изменился, переименован/перемещён или папку отключили и подключили заново.
- Файл изменился (тот же путь, другой размер/дата) → импорт: другое содержимое — новая книга (старая остаётся; что это «та же» книга, мы не знаем).
- Папка отключена → книги остаются, память (`FolderFiles`) удаляется каскадом, разрешение отдаётся.

**6. Подборка по папке** — не делаем автоматически (рекомендация; решает владелец). Если владелец хочет — галочка при подключении «Сложить в подборку „<имя папки>“»: в `Folders` колонка `collectionId` (null, `ON DELETE SET NULL`) в той же миграции v5, и каждая книга-результат (добавлена или дубль) этой папки попадает в обычную подборку (`CollectionRepository`), которую можно править как любую. Подпапки подборками не становятся.

**7. Интерфейс.** Экран «Папки» (из меню библиотеки): своя папка с подсказкой (iOS: «Файлы → На iPhone → BookApp»; Android: «по кабелю с компьютера: Android/data/…/Books»), подключённые папки (имя, когда смотрели, «нет доступа — подключить заново»), «Подключить папку», «Отключить» (подтверждение: книги останутся). Все строки — ARB. Бесплатная часть (флаг Pro не нужен).

## Отвергнуто
- Читать книги прямо из папки без копии (ADR 0005): пропадёт файл — пропадёт книга, закладки iOS ненадёжны.
- Пакеты (`file_picker` с выбором папки, `shared_storage`, `docman`, `androidx.documentfile`): ADR 0001; `DocumentFile.listFiles` ещё и медленный (запрос на каждый файл), `DocumentsContract` — один запрос на папку.
- Хэш каждого файла при каждом сканировании — дорого на сотнях книг; путь + размер + дата достаточно.
- Удалять файл из папки при удалении книги — приложение не трогает файлы пользователя.
- Ссылка «книга ↔ файл папки» в базе — правилам выше не нужна, а архив даёт несколько книг.
- Фоновое отслеживание (`FileObserver`, `NSFilePresenter`, WorkManager) — ADR 0005.
- Подпапки → подборки автоматически: неожиданные подборки, сложные правила при переносе файлов.

## Последствия
- Почти вся логика (`planScan`, своя папка, правила памяти, тихий импорт) — чистый Dart и тестируется на Windows с временной папкой и фейками канала; Android проходится на эмуляторе целиком (своя папка — через `adb push`, SAF — через «Загрузки/Книги»).
- Нативного кода +~100 строк Kotlin и +~100 Swift, только в существующих файлах; тест-сторож сверяет 4 новых метода и ключи `Info.plist`.
- iOS проверяется только на iPhone: своя папка — просто ключи (низкий риск, но меняет поведение «Открыть в» из «Файлов»); подключённые папки и iCloud — самый рискованный шаг, отдельным коммитом.
- База v5; размер на диске — книги из папок хранятся дважды (оригинал + копия библиотеки); для книг (единицы МБ) приемлемо.
