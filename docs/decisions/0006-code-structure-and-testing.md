# 0006. Структура кода и тестирование

- Статус: предложено (архитектор, 2026-10-19)
- Связано: 0001–0005

## Контекст
Самая рискованная логика (парсеры, кодировки, токенизация, темп, позиция) не зависит от экрана, и её можно полностью проверить на Windows. Экран и нативные части проверяются дороже (эмулятор, облачная сборка, iPhone). Структура должна держать эту границу.

## Решение
```
lib/
  app/        запуск, тема, локализация, корневая навигация
  book/       ЧИСТЫЙ DART: model/ (ADR 0002), parsers/ (epub, fb2, txt),
              encoding/, tokenizer/, import/ (определение формата, конвейер)
  speed/      ЧИСТЫЙ DART: orp, timing, chunker (фразы), sentences, rsvp_engine
  data/       drift (db, таблицы, миграции), репозитории, content_store (файлы книг)
  layout/     Flutter: paginator (TextPainter), page model, page painter, кэш разбивки
  platform/   обёртки каналов: files_channel.dart, screen_channel.dart (с фейками)
  features/   library/, reader/, speed/ (экраны RSVP и подсветки), settings/, stats/
  l10n/       app_ru.arb
test/         зеркалит lib/; test/fixtures/ — маленькие книги
```
Правила:
- `book/` и `speed/` не импортируют `package:flutter` (проверяет тест-сторож по тексту файлов). Поэтому их можно гонять в изоляте и тестировать без виджетов.
- Экраны не обращаются к базе и файлам напрямую — только через провайдеры Riverpod над репозиториями.
- Нативный код — только в существующих файлах шаблона (`AppDelegate.swift`/`SceneDelegate.swift`, `Info.plist`, `MainActivity.kt`, `AndroidManifest.xml`), без новых файлов и целей Xcode.
- Каждый нативный вызов в Dart имеет тип-функцию и фейк для тестов (опыт MoneyAPP).

**Тестирование.**
| Что | Как |
|---|---|
| Кодировки | UTF-8 (с BOM и без), 1251, KOI8-R, мусор; короткие и длинные тексты |
| Парсеры | эталонные «снимки» модели (JSON) для каждой книги из `fixtures/`: FB2 (1251, с картинками, сносками, стихами), FB2.ZIP, EPUB 2 и 3, TXT lib.ru, битые файлы |
| Токенизатор, ORP, темп, фразы, предложения | табличные тесты (вход → ожидаемые токены/мс), русский и английский |
| Движок RSVP | подставные часы: старт, пауза, разгон, назад по предложению, автопауза главы |
| Позиция | перенос по якорю после смены версии токенизатора; RSVP → чтение → то же слово |
| Вёрстка | `flutter test` с тестовым шрифтом: слова не теряются и не повторяются, смена размера сохраняет слово, кэш совпадает с пересчётом |
| База | in-memory drift, тесты миграций |
| Сторожа | имена каналов в Dart/Swift/Kotlin, ключи `Info.plist`, отсутствие Flutter в `book/` и `speed/` |
| Устройство | tester: набор «трудных книг» (большая книга на 500 тыс. слов, странные кодировки, EPUB без оглавления) на эмуляторе; владелец — чек-лист этапа на iPhone |

Книги в `fixtures/` — только общественное достояние или сгенерированные; большие «трудные» книги лежат вне репозитория.

**Ориентиры скорости (телефон):** импорт FB2 на 3 МБ — до 3 с; открытие книги из кэша — до 1 с; листание и RSVP — без рывков (60 кадров/с).

## Отвергнуто
- Отдельные Dart-пакеты (`packages/book_core`) — сейчас лишняя сложность; граница папок + сторож дают то же самое.
- Классические слои `domain/` + `data/` + `presentation/` для всего: у нас «предметная» часть — это книги и скорочтение, их и выделяем.
- Моки (`mockito`, `mocktail`) — хватает фейков и in-memory базы.

## Последствия
- 70–80% логики проверяется `flutter test` на Windows за секунды.
- Добавить формат = парсер в `book/parsers/` + снимок в `fixtures/`; остальное не трогается.
