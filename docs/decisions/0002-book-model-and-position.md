# 0002. Единая модель книги, хранение и позиция чтения

- Статус: предложено (архитектор, 2026-10-19)
- Связано: 0001, 0003 (вёрстка), 0004 (токены), 0005 (импорт)

## Контекст
Форматы разные (EPUB, FB2, FB2.ZIP, TXT; позже DOCX, PDF с текстом, MOBI), а читалка, вёрстка и скорочтение должны работать с одним представлением. Обычное чтение и скорочтение обязаны делить позицию ровно до слова. Книга на 500 тыс. слов («Война и мир») — около 3 МБ текста.

## Решение
**Одна модель, в которую каждый формат превращается при импорте** (чистый Dart, без Flutter):
```
BookContent { meta, toc: [TocEntry(title, level, sectionIndex)], sections: [Section] }
Section     { title?, blocks: [Block] }            // глава / раздел FB2 / файл spine EPUB
Block       = Heading(level) | Paragraph(style) | Image(assetId, w, h) | Separator
              style: normal | epigraph | poem | quote | subtitle | note
Paragraph   { text: String, spans: [Span(start, end, emphasis|strong|noteRef(id))] }
meta        { title, authors, series, lang, annotation, coverAssetId?, sourceFormat }
```
Слова в файле **не хранятся**: их детерминированно получает токенизатор (ADR 0004) при открытии книги. Результат — массив токенов с полями `blockIndex`, `charStart`, `charEnd`, флагами. Номер слова в книге (`wordIndex`) — его место в этом массиве.

**Хранение.** На каждую книгу — папка `books/<bookId>/` в каталоге поддержки приложения:
- `source.<ext>` — копия исходного файла (нужна для повторного разбора, когда улучшим парсер);
- `content.v<N>.json.gz` — модель (`GZipCodec` из `dart:io`), N — версия парсера;
- `cover.jpg|png`, `img/<assetId>` — обложка и иллюстрации;
- `pages-<layoutKey>.bin` — кэш разбивки на страницы (ADR 0003).

В базе (drift) — только то, что ищут, сортируют и меняют: книги (метаданные, хэш, путь, число слов, версия парсера, позиция, даты), подборки, папки, сессии чтения, настройки. Текст в SQLite не кладём: запросов к нему нет, а импорт и удаление книги файлами проще и быстрее.

Разбор при импорте — в фоновом изоляте (`Isolate.run`), интерфейс не замирает.

**Позиция чтения** = `wordIndex` + страховочный якорь `(sectionIndex, blockIndex, charOffset)` (номер блока — внутри главы). Процент прочитанного = `wordIndex / wordCount`. Если поменялась версия токенизатора или парсера, позиция восстанавливается по якорю, а `wordIndex` пересчитывается. Позицию сохраняем при перелистывании и выходе (с задержкой ~1 с, не на каждое слово).

**Дубли и повторный импорт.** SHA-256 исходного файла. Совпал — книгу не дублируем, говорим «уже в библиотеке» и поднимаем её наверх. Тот же текст в другом файле (EPUB и FB2 одной книги) в v1 считаем разными книгами. Версия парсера в базе меньше текущей → при открытии книга тихо разбирается заново из `source`, позиция переносится по якорю.

**Обложка.** EPUB: `cover-image` или meta cover; FB2: `coverpage` (base64 из `<binary>`). Нет обложки — рисуем свою: название на пастельном фоне (цвет из хэша).

**Иллюстрации в v1 — да, простые.** Картинка = отдельный блок по ширине страницы (не выше страницы), извлекается в файл при импорте. В скорочтении картинки пропускаются. Сноски FB2/EPUB: метка в тексте, текст сноски — по нажатию во всплывающем окне; в скорочтении метки пропускаются. Таблицы — плоским текстом.

## Отвергнуто
- **Блоки и слова в SQLite** (строка на абзац или слово): база в сотни МБ, медленный импорт, пользы нет.
- **Хранить в файле готовые токены**: файл в 3–5 раз больше, а токенизация 500 тыс. слов занимает доли секунды.
- **Позиция как процент или номер страницы**: зависит от шрифта и экрана, не годится для перехода в скорочтение на то же слово.
- **Не хранить исходник**: экономит место, но после исправления парсера книгу пришлось бы добавлять заново.

## Последствия
- Новый формат = только новый парсер в модель; читалка и скорочтение его «не замечают».
- Место: исходник + сжатая модель ≈ 1,5–2 размера файла (обычно 1–10 МБ на книгу).
- Токенизатор — часть «договора» о позиции: его изменение = новая версия + перенос по якорю, это покрывается тестами.
