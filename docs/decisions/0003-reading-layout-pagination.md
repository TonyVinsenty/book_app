# 0003. Вёрстка обычного чтения: настоящие страницы

- Статус: предложено (архитектор, 2026-10-19)
- Связано: 0002 (модель), 0004 (ведущая подсветка)

## Контекст
Владелец хочет «стр. N / M», листание, тап для показа интерфейса, A−/A+, долгое нажатие на слово → скорочтение и подсветку слова после возврата. Номера страниц зависят от шрифта, размера, интервала, полей и экрана. Вёрстку текста во Flutter (`TextPainter`) можно делать только в главном изоляте.

## Решение
**Постраничная вёрстка своим кодом, лениво по главам, с кэшем.**

1. **Разбивка.** Для каждого абзаца главы — `TextPainter` по ширине страницы; по `computeLineMetrics()` набираем строки, пока они помещаются по высоте. Абзац может разорваться между страницами по границе строки. Страница = `[(blockIndex, firstLine, lastLine)]`, плюс первый и последний `wordIndex`.
2. **Рисование.** Страница рисуется `CustomPainter`-ом: для разорванного абзаца рисуется тот же `TextPainter` целого абзаца со сдвигом и обрезкой по строкам. Поэтому переносы строк на странице совпадают с разбивкой точь-в-точь (в том числе при выравнивании по ширине).
3. **Слово под пальцем и подсветка.** `getPositionForOffset` → символ → `wordIndex` (по токенам из ADR 0004). Подсветка слова после скорочтения и ведущая подсветка — `getBoxesForSelection` по `charStart..charEnd` токена.
4. **Лениво и в фоне.** При открытии размечается текущая глава (десятки мс) — книгу сразу можно читать. Остальные главы размечаются порциями между кадрами (≤ 8 мс за кадр). Пока разметка не закончена, внизу «стр. 15 / ≈ 820» (оценка по числу символов), потом точное число.
5. **Кэш.** `layoutKey` = хэш(шрифт, размер, интервал, поля, выравнивание, размер экрана, версия вёрстки). Разбивка сохраняется в `pages-<layoutKey>.bin`; повторное открытие с теми же настройками — мгновенно. Хранить 2–3 последних ключа.
6. **Смена шрифта / поворот.** Запоминаем `wordIndex` первого слова на странице → переразмечаем текущую главу → открываем страницу, где это слово. Номера страниц сохраняются от этого слова, а не по номеру страницы.
7. **Переносы слов.** В v1 по умолчанию выравнивание влево, «по ширине» — опция. Русских переносов во Flutter нет; свой расстановщик (паттерны Лианга + мягкий перенос) — после v1, если выравнивание по ширине будет некрасивым.
8. **Перелистывание** — сдвиг страницы (без «загиба»); свайп влево/вправо тоже листает.

**Тап-зоны (обычное чтение):** левая треть — назад, правая треть — вперёд, середина — показать/скрыть интерфейс. Долгое нажатие на слово — скорочтение с этого слова. Отражение зон для левшей — настройка позже.
**Тап-зоны (скорочтение):** тап в любом месте = пауза + элементы управления; повторный тап по слову = продолжить.

## Отвергнуто
- **Сплошная прокрутка с «виртуальными экранами».** Проще (готовый ленивый список), но «стр. N» скачет при прокрутке, листание тапом неточное (полстроки обрезано), и это не то, чего хочет владелец. Оставляем как возможный режим после v1.
- **Только оценка страниц (символы ÷ символов на страницу).** Дёшево, но «последняя страница» оказывается полупустой или не той; годится лишь как временное число до конца разметки.
- **Разметка всей книги при открытии.** На книге в 500 тыс. слов — несколько секунд ожидания при каждой смене размера шрифта.
- **Вёрстка через WebView (EPUB как HTML).** Тяжело, медленно, плохо синхронизируется с RSVP по словам, плохо проверяется на iOS.

## Последствия
- Своя вёрстка — самый сложный кусок интерфейса (~600–900 строк), но он даёт точные страницы, точное попадание по слову и общую основу для ведущей подсветки.
- Проверки в `flutter test` (тестовый шрифт детерминирован): ни одно слово не теряется и не повторяется между страницами; после смены шрифта открыта страница с тем же словом; картинки и заголовки не разрываются.
- Производительность проверяем на «трудных» больших книгах на телефоне (tester).

## Дополнение 1 (6.8): сдвинутая страница
- Статус: принято (решение владельца + архитектор, 2026-10-19)

**Контекст.** После скорочтения строка с последним словом должна оказаться на той же высоте, где было слово на экране RSVP (середина экрана). Обычная разбивка этого не даёт: слово может быть в первой или последней строке страницы. Решение владельца: «сдвинутая» страница начинается раньше, дальше листание идёт от сдвига (без повторов и пропусков в обе стороны), номер приблизительный («≈ 12 / 33»), при смене главы, шрифта или размера экрана — снова обычная разбивка.

**Решение.**
1. **API.** `ChapterLayout shifted({required int word, required double lineCenterY})` и `ChapterLayout unshifted()`; поле `bool isShifted`. Обе возвращают новый объект с **теми же** `_BlockLayout` (без новой вёрстки текста — только разбивка, единицы мс). Владение painter-ами переходит к новому объекту: старый можно дочитать (ничего не освобождено), но `dispose()` вызывать нельзя. В читалке это одна строка: `_layouts[s] = _layouts[s]!.shifted(...)`. `shifted` всегда считает от исходных блоков (сдвиг не накапливается); `unshifted` у обычной разбивки возвращает `this`. Параметр в `build` отвергнут: заново верстает весь текст главы (на длинной главе — заметная пауза).
2. **Цель.** `lineCenterY` — в координатах страницы; считает читалка: `H/2 − 20` (верхнее поле), при отрисовке — по текущему размеру экрана (если экран повернули во время скорочтения, сдвиг считается уже для нового). Раскладка зажимает его в `[половина строки, высота страницы − половина строки]`.
3. **Выбор начальной строки.** От строки слова идём назад по строкам и блокам, считая высоты по правилам `_paginate` (промежуток между блоками = max(spaceAfter, spaceBefore); у верха страницы промежутка нет). Берём начало, при котором центр строки слова ближе всего к цели. Нельзя начинать: внутри `keepTogether`-блока (заголовок, разделитель) — только с его начала; сразу после блока с `keepWithNext` (заголовок остался бы в конце предыдущей страницы без текста) — переносим начало на сам заголовок. Если лучшее начало — первая строка главы (слово близко к началу), это и есть обычная страница 0: строка выше цели, «как можно ближе».
4. **Разбивка.** Глава режется в начальной строке на кусок A = [начало главы, сдвиг) и B = [сдвиг, конец главы); каждый размечается вперёд существующим `_paginate` (получает диапазон); страницы = A ++ B, слова страниц (`firstWord/endWord`) считаются по общему списку как сейчас. Последняя страница A может быть неполной (как конец главы). Заполнение A «с конца» (короткой была бы первая страница главы) отвергнуто: нужен второй алгоритм с правилами заголовков — больше кода и тестов; вернуться можно, если короткая страница перед сдвигом будет мешать.
5. **Проверка.** После разбивки, если слово не попало на первую страницу B (крайние случаи с заголовками, строка выше страницы), возвращаем обычную разбивку. `isShifted = false`, если начало совпало с границей обычной страницы (разбивка тогда и так совпадает с обычной) — номер точный.
6. **Слово и номер.** `pageOfWord`, `wordAt`, `wordBoxes`, `paintPage`, `pageText` работают без изменений (страницы упорядочены). `_showWord` открывает `pageOfWord(word)` сдвинутой раскладки и подсвечивает слово как сейчас. Нижняя строка при `isShifted` — новая строка ARB `readerPageOfChapterApprox` («≈ {page} / {count}»), то же для чтения с экрана. `_PagePainter` перерисуется сам (новый объект раскладки).
7. **Сброс.** Уход в другую главу (`_next/_previous`) — оставленную главу в кэше заменяем на `unshifted()` (без новой вёрстки); вернувшись, читатель видит обычные страницы. Смена шрифта/размера — `_relayoutIfNeeded` и так всё очищает. Новое скорочтение в той же главе — новый `shifted` от исходных блоков.
8. **Позиция и кэш.** Сохраняется, как и раньше: после скорочтения — последнее показанное слово, при листании — первое слово страницы; после перезапуска откроется обычная страница с этим словом (прочитанное не теряется). Кэш `pages-<layoutKey>.bin` (п. 5, ещё не сделан) хранит только обычную разбивку; сдвиг никогда не пишется на диск.

**Тесты** (`chapter_layout_test.dart`): для многих слов-якорей и размеров страниц — `expectExactSplit` и `expectWordsTouchable` на сдвинутой раскладке (листание вперёд и назад от сдвинутой страницы без повторов и пропусков); центр строки слова в пределах половины строки от цели (кроме начала главы — там `!isShifted` и страница 0); заголовок не разорван и не оторван от следующей строки; `shifted(...).unshifted()` = обычная разбивка; `shifted` от сдвинутой = от обычной.

**Последствия.** Изменения малые: `_paginate` с диапазоном + выбор начала (~80–120 строк). Число страниц главы при сдвиге может быть на 1 больше — поэтому «≈». Правило владения painter-ами нужно записать в комментарии к `shifted/unshifted`.

## Дополнение 2 (этап 8): настройки, страницы всей книги, кэш
- Статус: предложено (архитектор, 2026-10-20)

**Контекст.** Этап 8 добавляет настройки текста (шрифт, размер, интервал, поля, выравнивание, палитра, ночь), «стр. N / M» по всей книге, ползунок и оглавление с номерами страниц. П. 4–6 решения выше нужно уточнить: что входит в ключ кэша, где идёт разметка, как не терять место.

**Решение.**
1. **Настройки.** `ReadingSettings` (неизменяемый объект): `font` (`BookFont`), `fontSize`, `lineHeight`, `margins` (уровень), `align` (влево / по ширине), `palette` (`ReadingPalette`), `night` (как в системе / день / ночь). Хранение — таблица настроек, по ключу на поле (`reading.font`, …; новых таблиц и миграции нет); неизвестное или битое значение → значение по умолчанию. Провайдер Riverpod: читалка и тема приложения следят за ним, изменения видны сразу.
2. **Что влияет на вёрстку.** `PageStyle` получает `align`; поля превращаются в размер страницы (читалка вычитает их из области). **Цвет в равенство «вёрстки» не входит:** смена палитры или ночи перестраивает painter-ы текущей главы в памяти (десятки мс), но номера страниц и кэш остаются. Системный масштаб шрифта к тексту книги **не применяется** (размер задаёт A−/A+; при первом запуске размер по умолчанию = 18 × системный масштаб, округлённо); к интерфейсу — применяется.
3. **Размер страницы не прыгает.** Панели появляются поверх страницы (не сдвигают её). Область страницы считается от `MediaQuery.viewPadding` (постоянные вырезы экрана), а не от `padding`, иначе показ/скрытие строки состояния вызывал бы переразметку. Строка состояния телефона во время чтения — по решению владельца (`SystemChrome`, без нативного кода; на iPhone проверить в облачной сборке).
4. **Место при смене настроек.** Якорь — `_word` (первое слово страницы, или слово после скорочтения/перехода). Переразметка открывает страницу с якорем и **не меняет якорь**: серия A+ A+ A− возвращает на исходную страницу, а не «уползает» вперёд. Якорь меняется только листанием, ползунком, оглавлением, скорочтением. Тест обязателен.
5. **Разметка всей книги — без отдельного изолята.** Вёрстка текста (`TextPainter`) надёжно работает только в главном изоляте, поэтому фоновая разметка — это работа порциями в главном: `SchedulerBinding.scheduleTask(…, Priority.idle)`, бюджет ~6 мс на порцию, порция = несколько абзацев (не целая глава: длинная глава дала бы рывок). Во время анимаций и скорочтения (работает тикер) Flutter сам откладывает такие задачи. Для этого `_BlockLayout` делится на «метрики» (высоты строк, начала строк в символах, отступы, флаги `keep*`) и painter: `_split`/`_withWords` работают только с метриками; разметчик книги (`BookPagination`) считает метрики абзаца и сразу освобождает painter (память не растёт). Число страниц главы обязано совпадать с `ChapterLayout.build` — общий код, тест на всех тестовых книгах.
6. **Результат разметки** — для каждой главы список первых слов страниц (обычная, не сдвинутая разбивка). Отсюда: число страниц главы и книги, номер страницы книги для любого слова (двоичный поиск), слово для перехода ползунком, номера страниц в оглавлении. Пока не все главы размечены — «стр. 15 / ≈ 820»: неразмеченные главы оцениваются по числу символов × средняя плотность уже размеченных. Сдвинутая страница (дополнение 1) — тоже «≈».
7. **Ключ кэша.** Строка `v<версия вёрстки>|p<версия разборщика>|t<версия токенизатора>|<шрифт>|<размер>|<интервал>|<поля>|<выравнивание>|<ширина>x<высота страницы, округл. до 0,1>`. Файл `books/<id>/pages/<первые 16 знаков SHA-256 строки>.json` (пакет `crypto` уже есть), внутри — сама строка (проверка при чтении) и списки первых слов по главам; размеченные не до конца главы просто отсутствуют — при следующем открытии разметка продолжается. Хранить 3 последних по времени использования, остальные удалять; удаление книги удаляет папку. Цвет, палитра, ночь в ключ не входят. **Версию вёрстки поднимать** при любой правке правил разбивки, `PageStyle` или файлов шрифтов (`tool/fonts`).
8. **Сверка.** Когда глава реально размечается для показа, её первые слова страниц сравниваются с кэшем; расхождение → кэш главы заменяется (номера исправляются сами). Запись файла — через временный файл, не чаще раза в несколько секунд и при уходе из книги.
9. **Смена настроек.** Текущая глава — сразу (п. 4); проход по книге начинается заново для нового ключа (старый проход отменяется счётчиком поколений); если файл для ключа уже есть (вернулись к прежнему шрифту) — числа мгновенно. При перетаскивании ползунка размера в окне настроек переразметка — не чаще ~150 мс.

**Уточнение 8.2 (2026-10-20).** На Android `viewPadding.top` при спрятанной строке состояния тоже меняется (остаётся только вырез камеры), поэтому читалка берёт **наибольший** верхний отступ, виденный при этом размере экрана (сброс — при смене размера/повороте); страница не прыгает ни на Android, ни на iPhone без выреза. Строка состояния: спрятать — `SystemChrome.setEnabledSystemUIMode(manual, overlays: [bottom])`, показать — `manual` со всеми; `edgeToEdge` не годится — на Android после него строка больше не прячется. Нижняя системная полоса не трогается.

**Отвергнуто.** Отдельный изолят с вёрсткой — ненадёжно для `dart:ui`, и шрифты там не загружены. Кэш в базе drift — лишняя миграция ради данных, которые можно потерять без вреда. Хранить painter-ы всех глав — сотни МБ на больших книгах. Номер страницы «внутри главы» вместо книги — проще, но владелец просил «по всей книге».

**Последствия.** Правка `chapter_layout.dart` (метрики отдельно от painter) — самый рискованный шаг, защищён тестами «слова не теряются» и «число страниц совпадает». Новых пакетов и нативного кода нет. Производительность прохода — на «Войне и мире» (566 тыс. слов) на эмуляторе и iPhone.
