# 0005. Библиотека, импорт, папки на телефоне

- Статус: предложено (архитектор, 2026-10-19); выбор по папкам — за владельцем
- Связано: 0001 (свой канал), 0002 (хранение, дубли); дополнение 1 — этап 7 (EPUB, ZIP, обложки, дубли, очередь, входящие файлы)

## Контекст
Книги приходят тремя путями: выбор файла, «Поделиться / Открыть в» (Telegram, «Файлы», Safari, почта), папки на телефоне. iOS не даёт приложению свободно читать файловую систему, Android с 11-й версии — тоже (только через SAF).

## Решение
**Конвейер импорта (общий для всех путей):** файл → копия во временную папку → формат по содержимому, а не только по расширению (`PK` + `mimetype=application/epub+zip` → EPUB; ZIP с одним `.fb2` → FB2.ZIP; XML с `<FictionBook` → FB2; иначе TXT, если декодируется как текст) → SHA-256, проверка дубля → разбор в изоляте → файлы книги + строка в базе. Ошибка → понятное сообщение («файл повреждён», «формат пока не поддерживается»), без падения. Несколько файлов — очередью с прогрессом.

TXT: абзацы по пустым строкам или по отступу; склейка «жёстких» переносов (старые файлы lib.ru по ~70 символов); главы по строкам «Глава …», «ЧАСТЬ …», «Chapter …», одиночным римским цифрам, коротким строкам ЗАГЛАВНЫМИ.

**Платформенный канал `<appId>/files`** (Swift в существующих файлах шаблона, Kotlin в `MainActivity.kt`):
- `pickBooks()` → пути к копиям (iOS: `UIDocumentPickerViewController(asCopy: true)`, мультивыбор; Android: `ACTION_OPEN_DOCUMENT`, копия в `cacheDir`);
- входящие файлы: из нативной части в Dart вызов `onIncomingFiles`, плюс `takeInitialFiles()` для холодного запуска. iOS: типы в `CFBundleDocumentTypes` + `UTImportedTypeDeclarations` для `.fb2`/`.fb2.zip`; файл берётся в `openURLContexts` и в `connectionOptions` при запуске, копируется с `startAccessingSecurityScopedResource`. Android: `intent-filter` `VIEW` и `SEND`/`SEND_MULTIPLE` (EPUB, FB2, ZIP, TXT, `application/octet-stream` с фильтром по имени);
- `setKeepScreenOn(bool)`;
- папки (ниже).
Тест-сторож сверяет имена канала и методов в Dart, Swift и Kotlin и ключи `Info.plist`.

**Папки — что реально можно:**
- **iOS, вариант А — «своя папка в „Файлах“».** Ключи `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`: в «Файлах» появляется «На iPhone → <Приложение>». Пользователь кладёт туда книги (или папки с книгами); приложение при запуске и возврате на экран пересканирует её и добавляет новое. **Нативного кода ноль.**
- **iOS, вариант Б — «подключить любую папку».** Выбор папки в «Файлах» → закладка с правом доступа (security-scoped bookmark) хранится в базе → при запуске и возврате папка пересканируется. Работает для «На iPhone» и iCloud Drive, но файлы iCloud могут быть ещё не скачаны (надо запускать загрузку), закладка иногда «протухает» — тогда просим выбрать папку снова. ~100 строк Swift. **Следить за папкой в фоне iOS не даёт** — только пересканирование при открытии.
- **Android:** `ACTION_OPEN_DOCUMENT_TREE` + постоянное разрешение (`takePersistableUriPermission`), пересканирование при возврате. ~80 строк Kotlin. Аналога варианта А на Android нет (папка `Android/data` скрыта).
- Книга из папки **копируется** в библиотеку (нужен исходник, ADR 0002); повторное сканирование сравнивает (путь, размер, дата) и только новое хэширует. Удаление файла из папки книгу из библиотеки не удаляет.

Рекомендация: А — в этапе «Папки» сразу (бесплатно), Б и Android SAF — там же следующим шагом.

**Подборки и сортировка.** Таблицы `collections` и `book_collections` (книга может быть в нескольких). Автоматические списки: «Все», «Читаю» (открыта, < 98%), «Прочитано» (≥ 98% или отмечено вручную). Сортировка: недавно открытые (по умолчанию), дата добавления, название, автор, прогресс. «Продолжить» — последняя открытая книга сверху. Удаление книги — с подтверждением, удаляет файлы, позицию и место в подборках; статистика сессий остаётся. «Убрать из подборки» — отдельное действие.

## Отвергнуто
- `receive_sharing_intent` / Share Extension — ADR 0001.
- Читать книги прямо из папки без копии: пропадёт файл — пропадёт книга; на iOS доступ по закладке ненадёжен.
- Фоновое отслеживание папок: на iOS невозможно, на Android расходует батарею — пересканирования при открытии достаточно.

## Последствия
- Весь импорт, кроме получения байтов файла, — чистый Dart и тестируется на Windows; путь целиком проходится на эмуляторе Android до iOS.
- iOS-части (входящие файлы, папка Б) проверяются только на iPhone — делаем их маленькими отдельными шагами.

## Дополнение 1 (этап 7, 2026-10-19)
Владелец подтвердил (2026-10-19): дубль → открыть имеющуюся книгу; входящий файл во время чтения → сразу открыть новую (несколько файлов — добавить, итог одной строкой); архив с несколькими книгами → добавить все.

**ZIP — контейнер.** Формат ZIP определяем по центральному каталогу (пакет `archive`, ADR 0001), а не по первой записи: есть `META-INF/container.xml` → EPUB (первая запись `mimetype` не обязательна — неаккуратные EPUB встречаются); иначе архив — коробка с книгами: каждый `.fb2` (а также `.epub`, `.txt`) внутри, на любой глубине папок, распаковывается во временную папку и идёт по конвейеру как отдельный файл (свой хэш, свой дубль, источник хранится **распакованным**: `source.fb2`). Так FB2 и FB2.ZIP одной книги — один дубль. Вложенные архивы не раскрываем. Книг внутри нет → «формат не поддерживается». Защита от «zip-бомбы»: файл книги в архиве — не больше 100 МБ в распакованном виде, всего — не больше 300 МБ. Битый архив → «файл повреждён».

**EPUB (2 и 3), чистый Dart, разбор в изоляте:**
- `container.xml` → OPF: метаданные (`dc:title`, `dc:creator` — авторы, `dc:language`, `dc:description`; серия — `calibre:series`/`series_index` или EPUB 3 `belongs-to-collection` + `group-position`), `manifest`, `spine` по порядку (`linear="no"` — тоже по порядку: обычно это обложка без текста, пустые разделы отбрасываются).
- XHTML → наши блоки (ADR 0002): `h1–h6` → Heading(уровень), `p`/`div` с текстом/`li`/`dd` → Paragraph, `blockquote` → цитата, стихи (`class` с `poem`/`stanza`/`verse`) — как у FB2, если узнаём, иначе абзацы; `hr` → Separator; `br` — перенос внутри абзаца; `em/i`, `strong/b` — как курсив/жирный FB2; таблицы — плоским текстом; `head`, `script`, `style` — пропуск; CSS не читаем. Картинки (кроме обложки) и сноски пока пропускаем, как в FB2 (этап 12); метки сносок (`epub:type="noteref"`) убираем, тексты сносок (`aside epub:type="footnote"`) не показываем.
- Разбор XHTML — тем же потоковым разбором `xml`, что FB2, в «мягком» режиме: HTML-сущности (`&nbsp;`, `&mdash;` — таблица HTML5 из пакета), без проверки вложенности тегов. Кодировка: BOM / `<?xml encoding=…?>` / `meta charset`, иначе UTF-8; есть наш декодер 1251/KOI8-R.
- **Главы:** оглавление из EPUB 3 `nav` (`epub:type="toc"`) или EPUB 2 NCX. Точки деления — начало каждого файла spine и каждая ссылка оглавления с якорем (`file.xhtml#id`): одна огромная глава «вся книга в одном файле» иначе тормозила бы вёрстку (ADR 0003). Файл без своей ссылки в оглавлении приклеивается к предыдущей главе (книги Gutenberg и Calibre режут файлы по размеру); оглавления нет → глава = файл, название — первый заголовок файла. Дерево оглавления — в той же форме, что у FB2.
- **Ошибки:** нет OPF / пустой spine / ни одного слова → «файл повреждён»; отдельный битый или отсутствующий файл spine пропускаем, остальное читаем. **DRM:** есть `META-INF/rights.xml` или `encryption.xml` шифрует хоть один файл текста → понятный отказ «книга защищена от копирования (DRM), такие книги открыть нельзя» (новая ошибка импорта). Шифрование только шрифтов (алгоритмы IDPF/Adobe «obfuscation») — не помеха, шрифты мы всё равно не берём.

**Обложка.** EPUB: элемент manifest с `properties="cover-image"` → `<meta name="cover">` → картинка с `cover` в id/имени → первая картинка первого файла spine, если в нём почти нет текста. FB2: `coverpage` → `<binary>` по ссылке (парсер, пропуская остальные картинки, вынимает только эту). Сохраняется **как есть** в `books/<id>/cover.<jpg|png|gif|webp>` (по сигнатуре байтов); больше 5 МБ или неизвестный формат — без обложки. Уменьшенных копий не делаем: экран грузит обложку с `cacheWidth` (Flutter сам декодирует уменьшенной) — своего кода меньше, пакет `image` не нужен. Версия парсера FB2 поднимается → старые книги получат обложку при следующем открытии (повторный разбор уже есть).

**База, схема v2** (миграция с тестом по `drift_schemas/`): `coverFile` (имя файла обложки или пусто) и `touchedAt` — время последнего «касания» (добавление, открытие, повторный импорт; при миграции = `openedAt` или `addedAt`). Список сортируется по `touchedAt` — новая книга и дубль оказываются сверху. Последняя книга при запуске по-прежнему по `openedAt`.

**Дубль** (SHA-256 совпал): книга не копируется, `touchedAt` обновляется. Один входящий файл → открываем имеющуюся книгу на сохранённом месте с подсказкой «Эта книга уже есть в библиотеке»; в пачке файлов — только счётчик «уже были: N». (Выбор владельца — см. ROADMAP.)

**Очередь** (`ImportQueue`, Riverpod, чистый Dart): все пути — «Добавить книгу», входящие, позже папки — кладут файлы в одну очередь; обработка строго по одному (память), новые файлы во время работы дописываются в хвост. Состояние: всего / готово / текущее имя → полоска «Добавляю 2 из 5…» в библиотеке; в конце — итог одной строкой («Добавлено 3, уже были 1, не получилось 1») с «Подробнее» (список файлов и причин). Временные копии удаляются после обработки каждого файла; при запуске чистятся остатки `cache/picked` и `cache/incoming`.

**Входящий файл и открытая книга.** Один файл → после импорта сразу открывается он (место в текущей книге уже сохранено; стек сбрасывается до «библиотека → новая книга», RSVP закрывается). Несколько файлов → остаёмся, где были, итог показывается снэкбаром. Холодный запуск: `main` до `runApp` спрашивает `takeInitialFiles()`; если файлы есть — последняя книга **не** открывается, стартуем с библиотеки, дальше по правилу выше.

**Android.** `launchMode="singleTask"` вместо `singleTop` (иначе «Открыть с помощью» из Telegram может запустить вторую копию приложения внутри Telegram); `taskAffinity=""` оставляем. Фильтры `VIEW` (схемы `content`, `file`) и `SEND`/`SEND_MULTIPLE` с типами: `application/epub+zip`, `application/x-fictionbook+xml`, `application/x-fictionbook`, `application/zip`, `application/x-zip-compressed`, `text/plain`, `application/octet-stream` (у `content://` нет расширения — фильтр по имени невозможен; приложение будет предлагаться и для чужих двоичных файлов, их отсеет определитель формата). `*/*` не берём. `text/plain` — только в `VIEW`: в `SEND` он предлагал бы приложение при пересылке любого текста и ссылок (TXT-файл открывается через «Открыть с помощью»). Копирование URI в `cache/incoming/<n>/<имя>` — в фоновом потоке (имя — `OpenableColumns.DISPLAY_NAME`); `onCreate` складывает файлы для `takeInitialFiles`, `onNewIntent` → `onIncomingFiles`.

**iOS** (проект на сценах: `SceneDelegate: FlutterSceneDelegate`). В `SceneDelegate.swift` — `scene(_:openURLContexts:)` и `urlContexts` из `connectionOptions` в `scene(_:willConnectTo:options:)` (с вызовом `super`) передаются в маленький приёмник в `AppDelegate.swift`: копия в `tmp/incoming/<n>/` (с `startAccessingSecurityScopedResource` — понадобится, когда в этапе 11 включим `LSSupportsOpeningDocumentsInPlace`), удаление копии из `Documents/Inbox`, буфер до `takeInitialFiles()`, дальше `onIncomingFiles`. `Info.plist`: к FB2 и TXT добавить `org.idpf.epub-container` (системный тип EPUB) и `public.zip-archive` (так `.fb2.zip` попадает в «Открыть в»; чужие архивы отсеет определитель). Сторож сверяет новые ключи и имена методов.

**Отвергнуто здесь:** пакеты для EPUB (`epubx`, `epub_plus` — своя модель и устаревший разбор, ADR 0001); пакет `image` для уменьшения обложек (хватает `cacheWidth`); хранить FB2.ZIP сжатым (экономия места не стоит отдельной ветки кода и разных дублей у FB2 и FB2.ZIP).
